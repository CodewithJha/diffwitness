# HACK47 OFFGRID — Reopen Gate

**Purpose:** Strict gate for any future product discovery.  
**Rule:** **FAIL = KILL.** Weak ideas do not progress because they sound interesting, fill a calendar hole, or reuse killed vocabulary.

A new opportunity must answer **all sixteen** questions with evidence. Missing, hand-wavy, or “interesting but occupied” answers are kills.

---

## Gate questions

1. **What exact failure occurs?**  
   Name the concrete failure mode — not a category slogan.

2. **Who experiences it?**  
   Specific professional role / buyer, not “everyone with an LLM.”

3. **How frequently?**  
   Recurrence evidence, not a one-off anecdote.

4. **What happens when it occurs?**  
   Observable consequence (wrong ship, lost money, legal exposure, silent corruption, etc.).

5. **What is the measurable/economic cost?**  
   Cost, time, risk, or irreversible damage — stated honestly; Unknown is allowed only if labeled.

6. **What do users currently do?**  
   Actual workaround today (manual check, vendor tool, ignore, spreadsheet).

7. **Why is the existing workflow insufficient?**  
   Gap in the *current* path, not nostalgia for a better world.

8. **What primary evidence proves the problem?**  
   Court opinions, postmortems, primary docs, reproducible incidents — not vibes or secondary blogs alone.

9. **What existing products already address it?**  
   Named incumbents, OSS, CLI, vendor checkboxes — searched, not assumed empty.

10. **Why are those products insufficient?**  
   Concrete insufficiency for this user/job — not “they’re big companies.”

11. **What is materially different about the proposed mechanism?**  
   Mechanism delta, not branding or UI polish.

12. **Why is it not merely a wrapper?**  
   Why a weekend CLI / Search box / Promptfoo README / vendor API paste is not the whole product.

13. **Why can one person build it?**  
   Solo scope through a hosted demo in the remaining OFFGRID window (when coding is allowed).

14. **Can the core value be demonstrated quickly?**  
   Honest 20–90s demo without fixture theater or fake integrations.

15. **Could the product continue after the hackathon?**  
   Plausible company/tool path — not a one-shot stunt that dies on 15 Oct.

16. **What evidence would cause us to kill it?**  
   Pre-committed kill criteria. If those appear, stop — do not rename and continue.

---

## Enforcement

| Outcome | Action |
|---|---|
| Any question fails, is Unknown without a plan, or is answered by renaming a killed idea | **KILL** |
| All sixteen pass with primary evidence and a real gap | May advance to validation only |
| Validation kill tests fail | **KILL** — do not force selection |

Do **not** allow weak ideas to progress simply because they sound interesting.
